Two things I want to flag because they'll bite silently:

- **The NVML index gotcha.** Under `CUDA_VISIBLE_DEVICES=1`, torch sees your card as `cuda:0`, but NVML uses *physical* indices — so it must read physical index 1, or you'd be measuring the wrong GPU's power. The script auto-resolves this from `CUDA_VISIBLE_DEVICES`, but if you ever launch differently, pass `--nvml_index 1` explicitly.
- **Verify two things against your patched repo:** the prompt template string (`"In: What action should the robot take to {}?\nOut:"`) and that int8/int4 loading via `BitsAndBytesConfig` matches how your `run_libero_eval` does it. If your eval script constructs quantization differently, mirror *its* path so the quantized arms are apples-to-apples with the success numbers.
